# Architecture

## Pipeline

```
complaint text
 -> normalize (NFC, strip URLs, keep Devanagari + Latin)      [preprocess.py]
 -> language tag (script + Hinglish lexicon; unknown -> other) [language.py]
 -> sklearn TF-IDF (1-2 grams) + LogisticRegression
     heads: domain, priority                                   [train.py / predict.py]
 -> confidence = min(domain_p, priority_p)
 -> if lang == other OR confidence < 0.45 OR domains within 0.08
     -> needs_human = true, domain = "Other / Unknown"
 -> department = lookup(domain)                                 [taxonomy.py]
 -> similar tickets = TF-IDF cosine vs. data/complaints.csv     [similar.py]
 -> template acknowledgment in ticket language, SLA hours locked [reply.py]
 -> optional Groq/Ollama polish of the TEMPLATE ONLY             [llm.py]
    (must preserve "N hour(s)" / "ghante"; falls back to template on failure)
 -> SQLite (local) / Postgres (prod) inbox + officer override      [store.py]
 -> Streamlit UI (app.py) / FastAPI (api.py)
```

## Hard rules
- sklearn always runs; the LLM never owns routing (domain/priority).
- Taxonomy (config/taxonomy.yaml) is frozen for v1 — 8 domains, 3 priorities.
- SLA number in any LLM-polished reply is validated by a unit-anchored regex
  (see nagrikmitra/reply.py::sla_regex) before being accepted; on failure,
  fall back to the template with `used = False`.
- v1 encoder is TF-IDF/sklearn, not MuRIL. UI copy: "MuRIL-style pipeline
  (v1 = TF-IDF; MuRIL planned)" — never "powered by MuRIL".
- v1.5 (FAISS, Whisper stub, CLIP stub, GIS stub) starts only after v1 is
  fully green (see Definition of Done in the README).

## Data flow / storage
- `data/complaints.csv` — synthetic training + similarity corpus, committed.
- `models/*.joblib` — pretrained sklearn models, committed (training optional).
- Inbox + override audit trail + accounts: SQLite at `data/nagrikmitra.db`
  (gitignored) by default, or Postgres when `DATABASE_URL` is set (see
  README's Deployment section) — same schema either way, see `store.py`.
- `reports/metrics.json` — honest evaluation numbers, regenerated by train.py.
