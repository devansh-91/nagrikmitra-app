# Nagarik Mitra (नागरिक मित्र)

## Problem statement
Citizens file municipal grievances in Hindi, English, or Hinglish and often
can't name the right department. A wrong first hop causes transfers, missed
SLAs, and lost trust. Nagarik Mitra detects the ticket's language, classifies
its civic domain, routes it to the correct department, scores priority and
assigns an SLA, abstains to a human reviewer when unsure, drafts a
first-response acknowledgment in the ticket's own language, and logs
everything to an officer inbox with a full override audit trail.

This is a B.Tech CSE (AI/ML) demo project, not a CPGRAMS replacement.
All reported metrics are real, measured numbers — see [Evaluation](#evaluation).

## Taxonomy

| Domain | Department | SLA driver |
|---|---|---|
| Roads | PWD (Public Works Department) | Priority-based |
| Lights | Municipal Corporation — Street Lighting Division | Priority-based |
| Water | Jal Board (Water Supply and Sewerage) | Priority-based |
| Waste | Solid Waste Management Department | Priority-based |
| Sanitation | Sewerage and Drainage Board | Priority-based |
| Electricity | Discom (Power Distribution Company) | Priority-based |
| Health | District Health Department | Priority-based |
| Other / Unknown | General Administration (human review) | — |

| Priority | SLA |
|---|---|
| High | 48 hours |
| Medium | 168 hours (7 days) |
| Low | 336 hours (14 days) |

Full taxonomy: [`config/taxonomy.yaml`](config/taxonomy.yaml).

## Setup
```bash
python3 -m venv .venv
source .venv/bin/activate       # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env            # optional: add GROQ_API_KEY to enable LLM polish
```
Training is **optional** — `models/domain.joblib` and `models/priority.joblib`
ship pretrained. To regenerate data / retrain from scratch:
```bash
python -m nagrikmitra.generate_data
python -m nagrikmitra.train
```

## Run
```bash
bash scripts/run_api.sh     # FastAPI at http://localhost:8000  (/health, /predict, ...)
bash scripts/run_ui.sh      # Streamlit UI
```

Example call:
```bash
curl -X POST http://localhost:8000/predict \
  -H "Content-Type: application/json" \
  -d '{"text": "bijli kaam nahi kar rahi hai transformer se sparking ho rahi hai", "use_llm": false, "channel": "web", "persist": true}'
```

## Evaluation
`reports/metrics.json` (regenerated by `train.py`) reports: test accuracy and
macro-F1 for both the domain and priority heads, the keyword-baseline domain
accuracy, per-language (en/hi/hinglish) slices, high-priority recall, and a
disclaimer that synthetic templates tend to be memorized. These are the
system's own numbers — figures from unrelated papers are never quoted here.

On the held-out test split (180 of 1,200 rows, stratified 70/15/15 by domain):

| Metric | Value |
|---|---|
| Domain head — test accuracy | 0.9944 |
| Domain head — test macro-F1 | 0.9944 |
| Priority head — test accuracy | 0.9889 |
| Priority head — test macro-F1 | 0.9890 |
| Keyword baseline — domain accuracy | 0.7333 |
| High-priority recall | 1.0000 |
| Language slice (en) — domain / priority accuracy | 1.0000 / 1.0000 |
| Language slice (hi) — domain / priority accuracy | 0.9821 / 0.9643 |
| Language slice (hinglish) — domain / priority accuracy | 1.0000 / 1.0000 |

The sklearn heads outperform the from-scratch keyword baseline by a wide
margin (~26 points of domain accuracy), which is the meaningful comparison —
not the near-ceiling test accuracy itself. As `reports/metrics.json` says:
synthetic complaint templates tend to be memorized, so treat these as
indicative of the pipeline working end-to-end, not a real-world benchmark.

## Limitations & next steps
- v1's encoder is TF-IDF + sklearn, not MuRIL. Fine-tuning MuRIL (Colab, not
  a local laptop) is planned Week 2+ work, not a v1 blocker.
- No voice, image, or GIS capability is implemented in v1 (FAISS/Whisper/CLIP/
  GIS are v1.5 stubs, started only after v1 is fully green).
- Synthetic training data — real-world accuracy will differ from `metrics.json`.
