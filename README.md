# Nagarik Mitra (नागरिक मित्र)

## Problem statement
Citizens file municipal grievances in Hindi, English, or Hinglish and often
can't name the right department. A wrong first hop causes transfers, missed
SLAs, and lost trust. Nagarik Mitra detects the ticket's language, classifies
its civic domain, routes it to the correct department, scores priority and
assigns an SLA, abstains to a human reviewer when unsure, drafts a
first-response acknowledgment in the ticket's own language, and logs
everything to an officer inbox with a full override audit trail.

This is a B.Tech CSE (AI/ML) demo project, not a CPGRAMS replacement.
All reported metrics are real, measured numbers — see [Evaluation](#evaluation).

## Taxonomy

| Domain | Department | SLA driver |
|---|---|---|
| Roads | PWD (Public Works Department) | Priority-based |
| Lights | Municipal Corporation — Street Lighting Division | Priority-based |
| Water | Jal Board (Water Supply and Sewerage) | Priority-based |
| Waste | Solid Waste Management Department | Priority-based |
| Sanitation | Sewerage and Drainage Board | Priority-based |
| Electricity | Discom (Power Distribution Company) | Priority-based |
| Health | District Health Department | Priority-based |
| Other / Unknown | General Administration (human review) | — |

| Priority | SLA |
|---|---|
| High | 48 hours |
| Medium | 168 hours (7 days) |
| Low | 336 hours (14 days) |

Full taxonomy: [`config/taxonomy.yaml`](config/taxonomy.yaml).

## Setup
```bash
python3 -m venv .venv
source .venv/bin/activate       # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env            # optional: add GROQ_API_KEY to enable LLM polish
```
Training is **optional** — `models/domain.joblib` and `models/priority.joblib`
ship pretrained. To regenerate data / retrain from scratch:
```bash
python -m nagrikmitra.generate_data
python -m nagrikmitra.train
```

## Run
```bash
bash scripts/run_api.sh     # FastAPI + web UI at http://localhost:8000  (/health, /predict, ...)
bash scripts/run_ui.sh      # Streamlit UI (alternate/legacy)
bash scripts/run_mcp.sh     # MCP server (stdio) for MCP clients, e.g. Claude Desktop
```
`scripts/run_api.sh` serves both the JSON API and `frontend/index.html` (citizen
submission form + officer dashboard) from the same process — open
http://localhost:8000 in a browser.

### MCP server
`mcp_server.py` exposes the routing engine as MCP tools (`classify_complaint`,
`list_tickets`, `get_ticket`, `update_ticket_status`, `override_ticket`,
`get_analytics`, `submit_to_gov_portal`) for any MCP client. Point a client at
`.venv/bin/python /absolute/path/to/mcp_server.py`.

`submit_to_gov_portal` does **not** submit to any real government portal —
CPGRAMS and state/municipal grievance portals have no confirmed public
submission API and gate their citizen forms with CAPTCHA/OTP specifically
against automated filing. It calls `gov_portal.MockGovPortalAdapter`, which
simulates the round trip (fake reference number, no network call). See
`gov_portal.py` for the `GovPortalAdapter` interface to implement against a
real portal if you obtain genuine, authorized API access to one.

## Deployment (free hosting on Render)
`api.py` serves the JSON API **and** `frontend/index.html` from one process
(see `app.mount("/", ...)` in `api.py`), so the whole app — citizen form,
officer dashboard, API — is a single web service. No separate frontend host
is needed.

This repo includes a [`render.yaml`](render.yaml) Blueprint for
[Render](https://render.com)'s free web service tier (no credit card
required):

1. Push this repo to GitHub (see below).
2. On [render.com](https://dashboard.render.com), **New +** → **Blueprint**
   → connect this GitHub repo. Render reads `render.yaml` and provisions the
   service automatically (`plan: free`).
3. In the service's **Environment** tab, set the secrets `render.yaml`
   leaves blank (`sync: false`): at minimum `OFFICER_SIGNUP_CODE` (a value
   you invent — required for officer self-registration; without it that
   endpoint is rejected outright). `GROQ_API_KEY`, `GOOGLE_CLIENT_ID`,
   `GOOGLE_CLIENT_SECRET`, `GOOGLE_REDIRECT_URI` are optional — leave them
   blank to run without LLM-polished replies / Google sign-in.
   `SESSION_SECRET` is auto-generated by the Blueprint.
4. Deploy. Render builds with `pip install -r requirements.txt` and runs
   `uvicorn api:app --host 0.0.0.0 --port $PORT`, and gives you a free
   `https://<name>.onrender.com` URL.

**Known limitation:** Render's free tier has no persistent disk, so
`data/nagrikmitra.db` (tickets, citizen/officer accounts) resets on every
redeploy and on periodic free-tier restarts. Fine for a demo/portfolio
deploy; if you need data to survive restarts, migrate `nagrikmitra/store.py`
off local SQLite onto a hosted DB (e.g. a free-tier Postgres from
[Neon](https://neon.tech) or [Supabase](https://supabase.com)) and add a
paid Render disk, or move to a host with persistent storage.

The free instance also spins down after ~15 minutes idle and takes ~30-60s
to wake on the next request — expected on a free tier, not a bug.

The MCP server (`mcp_server.py`) is stdio-based and meant for a local MCP
client (e.g. Claude Desktop) pointed at your machine — it is not part of the
web deployment above.

Example call:
```bash
curl -X POST http://localhost:8000/predict \
  -H "Content-Type: application/json" \
  -d '{"text": "bijli kaam nahi kar rahi hai transformer se sparking ho rahi hai", "use_llm": false, "channel": "web", "persist": true}'
```

## Evaluation
`reports/metrics.json` (regenerated by `train.py`) reports: test accuracy and
macro-F1 for both the domain and priority heads, the keyword-baseline domain
accuracy, per-language (en/hi/hinglish) slices, high-priority recall, and a
disclaimer that synthetic templates tend to be memorized. These are the
system's own numbers — figures from unrelated papers are never quoted here.

On the held-out test split (180 of 1,200 rows, stratified 70/15/15 by domain):

| Metric | Value |
|---|---|
| Domain head — test accuracy | 0.9944 |
| Domain head — test macro-F1 | 0.9944 |
| Priority head — test accuracy | 0.9889 |
| Priority head — test macro-F1 | 0.9890 |
| Keyword baseline — domain accuracy | 0.7333 |
| High-priority recall | 1.0000 |
| Language slice (en) — domain / priority accuracy | 1.0000 / 1.0000 |
| Language slice (hi) — domain / priority accuracy | 0.9821 / 0.9643 |
| Language slice (hinglish) — domain / priority accuracy | 1.0000 / 1.0000 |

The sklearn heads outperform the from-scratch keyword baseline by a wide
margin (~26 points of domain accuracy), which is the meaningful comparison —
not the near-ceiling test accuracy itself. As `reports/metrics.json` says:
synthetic complaint templates tend to be memorized, so treat these as
indicative of the pipeline working end-to-end, not a real-world benchmark.

## Limitations & next steps
- v1's encoder is TF-IDF + sklearn, not MuRIL. Fine-tuning MuRIL (Colab, not
  a local laptop) is planned Week 2+ work, not a v1 blocker.
- No voice, image, or GIS capability is implemented in v1 (FAISS/Whisper/CLIP/
  GIS are v1.5 stubs, started only after v1 is fully green).
- Synthetic training data — real-world accuracy will differ from `metrics.json`.
